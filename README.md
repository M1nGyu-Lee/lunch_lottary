# 점심복권

팀의 음식점 후보를 모아 두고 복권을 긁어 점심을 고르는 데스크톱 앱입니다.

## 사용법

1. **음식점 보관함**에서 이름, 위치, 음식 태그를 등록합니다.
2. **제로페이 공식 가맹점 검색** 버튼으로 공식 페이지를 엽니다. 버튼을 누르면 상호가 복사됩니다. 공식 페이지에서 지역을 선택하고 상호를 붙여넣어 주소가 일치하는지 대조한 뒤 확인 체크를 하고 **확인 완료**로 저장합니다. 이름이나 주소를 바꾸면 다시 확인해야 합니다.
3. **오늘의 추첨**에서 원하는 태그를 선택하고 **제로페이만 / 전체 음식점**을 고른 뒤 복권을 받습니다. 현재 조건에 해당하는 음식점이 0곳인 태그는 자동으로 비활성화됩니다. **최근 7일 실제로 먹은 곳 제외**를 켜면 식사 이력을 반영합니다. 기본값은 제로페이 확인 기록이 있는 매장이고 최근 식사 제외는 꺼져 있습니다.
4. 복권을 2% 이상, 설정한 노출률 이하로 긁었을 때만 재추첨할 수 있습니다. 재추첨 상한도 조정할 수 있습니다.
5. **찐막 추첨**을 누르면 일반 재추첨은 잠기고 붉은 불꽃이 나타납니다. 이어 **찐찐막 추첨**을 누르면 푸른 불꽃과 긁는 동안 강해지는 화면 흔들림이 나타납니다.
6. 결과를 충분히 긁으면 **우리 실제로 여기서 먹었어요** 버튼이 나타납니다. 식사 날짜를 입력하면 **추첨 · 식사 이력** 탭에 기록됩니다. 이력에서 나중에 날짜를 입력하거나 수정할 수도 있습니다.

## 데이터와 제로페이 확인

배포본에는 프로젝트 기본 음식점 목록이 포함되며, 음식점 보관함이 비어 있는 기기의 첫 실행 때 로컬 IndexedDB에 한 번 복사됩니다. 기존 목록이 있는 기기에는 기본 목록을 추가하지 않습니다. **교육장 공유를 켜기 전에는** 음식점 추가·수정·삭제와 추첨·식사 이력이 각 기기의 IndexedDB에 저장됩니다. 팀원이 파일로 목록을 주고받으려면 보관함의 **음식점 내보내기 / 음식점 가져오기**를 쓰세요. 이 파일에는 음식점만 들어가며 추첨·식사 이력은 포함되지 않습니다. **추첨 · 식사 이력** 탭의 **전체 백업 / 전체 백업 가져오기**는 음식점, 추첨·식사 이력, 설정을 함께 보관하는 개인 백업용입니다. 가져오기는 기존 목록과 이력을 유지하면서 중복을 건너뛰고, 백업에 설정이 있으면 설정은 백업 값으로 바꿉니다. 이전 버전의 전체 백업 파일도 음식점 가져오기에서 음식점만 추출해 읽을 수 있습니다.

현재 확인 가능한 공식 공개 조회 API와 공식 검색 페이지의 입력값 전달 규약을 찾지 못해, 자동 판정이나 검색 양식 자동 입력은 제공하지 않습니다. 공식 [가맹점 검색](https://zeropay.or.kr/UI_HP_009_03.act) 결과를 사람이 대조한 후 상태와 확인 날짜를 기록합니다. 확인 날짜가 없거나 90일이 지나면 앱이 재확인을 권합니다. **확인 완료**는 사용자의 확인 기록이며 실시간 보증이 아닙니다. 제로페이 가맹점이라도 결제 수단별 사용 가능 여부는 다를 수 있으므로 [제로페이 안내](https://www.zeropay.or.kr/UI_HP_010_03_03.act)에 따라 매장 상세의 결제 가능 수단을 확인하세요.

향후 네이버 지도 등 음식점 검색 서비스를 연결할 때는 검색 결과를 음식점 후보로 추가하고, 제로페이 상태를 별도 속성으로 유지하면 현재의 결제 조건 버튼과 함께 사용할 수 있습니다. 네이버 API 사용에는 별도의 제공 조건과 인증 정보 확인이 필요합니다.

## 교육장 내부망 공유

1. 호스트로 사용할 PC에서 **교육장 공유 → 이 PC를 호스트로 설정**을 누릅니다. 이 PC의 음식점과 추첨·식사 이력이 첫 공유 데이터가 됩니다. 호스트 PC의 앱을 켜 두세요.
2. 다른 PC에서 **교육장 공유 → 호스트에 참여하기**를 엽니다. 호스트 화면의 내부 IP 주소 하나와 12자리 공유 코드를 처음 한 번 입력합니다. 앱은 참여 전 이 PC의 개인 데이터 백업 JSON을 다운로드합니다.
3. 이후 참여 PC에서 앱을 실행하면 저장된 주소로 자동 연결합니다. 호스트의 IP가 바뀌어도 같은 네트워크에서 자동 검색 알림이 전달되면 새 주소로 연결합니다. 자동 검색이 차단된 네트워크에서는 새 주소를 다시 입력할 수 있습니다.

음식점 및 추첨·식사 이력은 호스트 PC가 원본을 보관합니다. 참여 PC는 약 2.5초 간격으로 최신 버전을 확인하고 SHA-256 해시가 일치할 때만 로컬 사본을 갱신합니다. 호스트 파일도 시작할 때 해시를 검증하며 이전 백업 파일로 복구를 시도합니다. 참여 PC에서 호스트 연결이 끊기면 저장된 목록은 볼 수 있지만 공동 데이터 수정과 추첨은 연결될 때까지 잠깁니다. 재추첨 설정과 태그 선택은 PC마다 따로 유지됩니다.

이 기능은 외부 서버 없이 교육장 내부망만 사용합니다. 호스트 PC의 방화벽에서 앱의 TCP 41781 포트 연결이 허용돼야 하며, PC 간 통신이 차단된 Wi-Fi에서는 사용할 수 없습니다. 자동 검색은 UDP 멀티캐스트 41782 포트를 사용합니다. macOS에서는 처음 실행할 때 로컬 네트워크 접근을 허용해야 합니다. 공유 코드는 교육장 사용자에게만 알려주세요.

## Mac에서 실행하기

1. GitHub Releases에서 Apple Silicon(M1·M2·M3 등)은 `LunchLottery-macOS-arm64-0.2.0.dmg`, Intel Mac은 `LunchLottery-macOS-x64-0.2.0.dmg`를 받습니다. Apple 메뉴의 **이 Mac에 관하여**에서 칩 또는 프로세서를 확인할 수 있습니다.
2. `.dmg`를 열어 **점심복권.app**을 **응용 프로그램** 폴더로 옮기고 실행합니다.
3. 교육장 공유를 사용하려면 로컬 네트워크 접근을 허용하고 Windows와 똑같이 호스트 IP와 공유 코드를 입력합니다.

Mac 앱에는 빌드 무결성을 위한 임시 서명을 적용하지만 Apple Developer ID 서명과 공증은 포함하지 않습니다. 처음 실행할 때 개발자 확인 안내가 뜰 수 있습니다. 직접 받은 이 앱을 실행하려면 [Apple의 실행 안내](https://support.apple.com/ko-kr/102445)에 따라 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**에서 해당 앱을 확인합니다.

## 개발

Node.js 24와 pnpm 11 기준입니다.

```bash
pnpm install
pnpm test
pnpm dev       # 브라우저 미리보기: http://127.0.0.1:4173
pnpm desktop   # 데스크톱 앱 실행
```

Windows에서 `pnpm dist:win`을 실행하면 `dist/`에 휴대용 `.exe`가 생성됩니다. macOS에서는 `pnpm dist:mac`으로 Intel과 Apple Silicon용 `.dmg`를 만듭니다. **Windows `.exe`는 macOS에서 실행되지 않습니다.** GitHub의 `main` 브랜치 또는 `v*` 태그를 푸시하면 Actions가 Windows·Intel Mac·Apple Silicon Mac에서 각각 빌드합니다. Mac 결과물은 DMG를 실제로 마운트한 후 앱 시작, 두 앱 사이의 음식점·추첨 이력 공유, 재시작 후 자동 연결, SHA-256 확인과 손상 백업 복구를 검사합니다. 빌드가 모두 통과하면 아직 없는 버전의 Release에 실행 파일, 소스 ZIP과 SHA-256 목록을 첨부합니다. 기존 Release가 있으면 새 결과물은 Actions 아티팩트로 보관됩니다. 단순 `git clone`에는 실행 파일이 포함되지 않으므로 사용자는 GitHub Releases에서 자신의 OS용 파일을 내려받아 실행하면 됩니다.

Windows 빌드에는 인증서 서명이 없습니다. 배포 범위를 넓힐 때 Windows 인증서와 Mac Developer ID 서명·Apple 공증을 설정하면 OS 경고를 줄일 수 있습니다.
Windows의 일부 제한된 실행 환경에서 Electron 렌더러가 시작 단계에 중단되어, 이 버전은 로컬 화면에 한해 렌더러 샌드박스와 GPU 가속을 끕니다. Node 통합은 꺼져 있고, 외부 제로페이 페이지는 기본 브라우저에서 열립니다.

## 구조

- `app/`: 화면, 추첨 규칙, IndexedDB 저장소
- `electron/`: 로컬 화면을 여는 안전한 데스크톱 셸
- `tests/`: 추첨 및 입력 검증
- `.github/workflows/build.yml`: Windows/macOS 자동 빌드
